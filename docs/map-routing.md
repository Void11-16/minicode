# 地图路线实现与约定

地图底图和标记仍使用 Leaflet + 高德瓦片。道路几何、公交方案和坐标校准经服务器调用高德 Web 服务，Key 不进入浏览器。路线编排集中在 `src/web/plan-routes.ts`，服务器负责读取快照、HTTP 生命周期和版本校验。

## 交通方式与路线证据

- 相邻停留点（景点、住宿、休息）之间优先采用 transport 条目的 `transport_mode`。餐厅候选只显示标记。
- 通过 `route_evidence_id` 复用规划工具的路线，必须同时匹配交通方式、城市和转换到同一坐标系的起终点。新采集的步行、驾车、公交及 OSRM 兜底路线都可以保存同一方案的几何，避免地图另选方案。
- 公交分别绘制步行接驳和乘车段，不连接不同分段之间未提供的几何。一个公交分段的多条 buslines 是备选线路，只采用第一条。
- 出租车使用驾车道路，保留出租车标签；骑行使用高德 v4 骑行接口。多个交通条目或端点冲突明确显示待确认，不猜测合并方式。
- 历史行程没有 transport 条目时，保留 1.5 公里内步行、其余驾车的默认方式。该默认方式不代表行程已核验。

## 缓存与时间含义

几何缓存为 30 天，查询耗时有效期为 30 分钟，每次读取及持久化都检查过期，运行中的服务不必重启。超过 30 分钟仍可绘制几何，但不会输出过期的查询耗时。规划证据是历史事实，单独输出“规划耗时”和采集时间，不被当成实时交通结果。

缓存键包含方向、交通方式、城市（公交）及 GCJ-02 精确端点。新格式使用 v2 命名空间，不沿用旧缓存中的推断方式和坐标舍入键。缓存限制 800 条，读写复制值，串行原子落盘。损坏或写入失败只影响缓存。

## 取消与并发

切换行程、关闭地图、账号重置或保存编辑会取消旧路线请求；切换日期会取消其他日期的预取，立即请求当前日。HTTP 连接断开会传播 AbortSignal 到坐标校准、限速队列和上游 fetch。相同路段可合并请求，各消费者独立取消，最后一个消费者离开才取消共享工作。工作区与高德客户端之间隔离在途请求。

坐标校准随可取消的路线请求执行，读取行程只返回现有坐标。校准结果变更快照后，前端重新读取行程和版本。校准失败状态短期保留 10 分钟，取消不会写成失败缓存。

## 版本、端点和状态

行程接口返回原始 JSON 内容的 SHA-256 `routeVersion`，路线请求携带 `version`。服务器在查询前和响应前验证版本；不一致返回 409。路线响应也带版本及每段的端点 ID 和 GCJ-02 坐标，浏览器检查版本、段数及逐段端点后才采用几何。

同一点、估算、无路线、缺少几何、配额不足、Key 异常、网络错误等状态分别展示。虚线表示未获得真实几何，公交接驳步行采用较长虚线。重试请求携带失败路段下标，保留成功路段，不重复查询它们。损坏行程返回 500，缺失行程返回 404，无效参数返回 400。

## 坐标校准

城市来自行程约束，不从标题猜测。候选必须匹配城市行政字段、地点名称、已知 POI ID，并位于原坐标 8 公里内；偏移比较统一使用 GCJ-02。过滤停车场等附属设施，相近同名分店存在歧义时保留原坐标。没有城市和 POI ID 时不自动改坐标，页面提示核实。已核验或已校准的条目不重复覆盖。

## 验证

`test/map-routes.test.ts` 覆盖交通方式、规划工具与地图复用、缓存边界、共享请求取消和 POI 匹配；`test/map-routes-http.test.ts` 覆盖 HTTP 取消、前后版本检查、错误状态及失败重试；`test/map-ui.test.ts` 执行页面实际函数，覆盖竞态、端点检查、日期优先级与关闭取消。

# 工具、上下文与任务预算

## 输入工作预算

默认 24,000 是完整输入的估算预算，不是模型的上下文容量。系统提示词、工具参数定义、历史（含 tool_calls）和临时注入内容统一计量。系数使用供应商返回的实际 prompt tokens 校准。预算使用字符估算，不能替代模型 tokenizer；更换较小窗口模型时，应调整配置，给模型输出预留空间。

每次模型请求前都检查，而非仅在用户新一轮消息开始时检查。超限时优先摘要旧历史，随后重新构造请求；仍超限时缩小可选状态/证据详情并只保留最近一组完整工具调用。全局约束、当前版本和跨天景点去重不会为凑预算被截断。若仍然超限，明确返回输入过大错误，避免把不完整约束交给模型。

普通发送和最终收尾同样经过完整输入检查。OpenAI 兼容及 DeepSeek Provider 暴露固定 systemPrompt；新增 Provider 时也应暴露这一属性。摘要请求禁用工具，遵守输入预算，供应商返回的 usage 计入相同会话和任务。

## 工具加载与保存反馈

read_file 全局常驻。save_itinerary、load_itinerary、validate_itinerary、plan_day_routes 在旅行模式常驻；普通模式可以通过目录显式激活。CLI 默认旅行模式，Web 采用界面当前模式，旅行评测显式启用旅行模式。原有未分类扩展工具的常驻策略保留。

save 的定义只精简说明，不删参数或改变既有数据含义。保存原本就执行完整质量校验，现在直接返回版本、strict 对应结果、前六个主要问题（含级别、日期、条目 ID、问题码）以及完整报告路径。逐日保存不再要求对同一版本立即重复校验，最终交付仍使用 validate_itinerary(strict=true)。只重新查询端点、方式或顺序已改变且没有匹配证据的路线。

## 动态上下文

每次保留全局需求、版本、日期进度和全部已选景点的跨天去重信息；只展开当前日时间线与优先待修问题。用户指定“第 N 天”优先；否则先补缺失日期，完成后定位具体日期的质量问题。

证据按当前日地点、必去点、最近查询的口碑对象与路线端点选择，去重后优先保留相关记录，其余只补少量近期候选。状态和证据详情通常分配 6,000/4,000 字符；输入紧张时进一步缩减。工具原文仍以 artifact 按需读取。

工具执行顺序保持不变，本次没有引入并行执行。

## 大工具结果与原文读取

单条工具结果进入历史前最多保留 3,000 字符，同批合计最多 8,000 字符（包含结果类型头和说明）。超出部分原文落盘到 `.minicode/artifacts/<session>/`，不增加额外模型摘要请求。地点、路线、校验和行程 JSON 使用字段投影，原生地点/路线文本会将尾部证据 ID 绑定回对应候选或交通段。完整记录放不下时标记省略数量；未知格式仍使用通用首尾和关键行预览。结构化 JSON 投影最多解析 2,000,000 字符，超大 JSON 回退到通用预览，完整内容仍可读取。

`read_file` 增加 `byte_offset`（0 起）和 `byte_limit`（4—2,000，默认 2,000）；与行号 `offset/limit` 互斥。字节模式只读取固定缓冲，不受行号模式 2MB 上限约束。页尾不完整 UTF-8 字符留给下一页，返回的 byte_offset 是实际消耗位置；必须沿返回游标继续，不能自行加固定长度。BOM 保留，非法编码或从字符中间开始会明确报错。行号模式遇到超长单行也返回未读部分的字节游标。

bash 的 stdout/stderr 各保留最多 15,000 字符首尾，分块解码 UTF-8，持续排空管道但不累积中间日志，不因输出过多而终止命令。中间丢弃量会明确标记，完整日志应由命令重定向到文件。工具结果归档保存工具实际返回的内容，不能恢复执行阶段已丢弃的日志；磁盘写入失败时仍保留有界预览和工具协议配对，并标明归档不可用。

## 统一执行预算

Web、CLI、旅行评测共用 createExecutionBudget。默认单任务硬上限：150 工具轮、300 次工具调用、2,000,000 累计 tokens、估算费用 3 元。按天分配的初始轮次仍然保留，上限不是必须消耗的配额。单个进行中的模型请求可能使费用或 token 总量跨过阈值；响应计量完成后停止后续请求。

续期和自动承接 steer 继续使用同一预算对象；新的独立用户请求建立新任务预算。费用按当前模型价格计算，缓存输入单独计价。task_budget_yuan 是单任务上限，budget_yuan 是会话累计上限，两者独立，费用上限为 0 表示不限制。

配置可通过 CLI `/config set <键> <值>` 或 `.minicode/config.json` 修改：

| CLI 键 | JSON 键 | 默认值 |
| --- | --- | --- |
| max_prompt_tokens | maxPromptTokens | 24000 |
| max_task_tokens | maxTaskTokens | 2000000 |
| max_tool_calls | maxToolCalls | 300 |
| max_task_rounds | maxTaskRounds | 150（最高 150） |
| task_budget_yuan | taskBudgetYuan | 3（0 不限） |
| budget_yuan | budgetYuan | 0（会话费用不限） |

## 观测和验证

会话 requestContexts 保存最近 200 次请求的系统提示、工具定义、历史、临时内容的字符量及估算输入 tokens；供应商返回 usage 后补充真实 prompt tokens 和缓存命中 tokens。只保存大小，不保存正文。记录不进入模型历史。Web 发送 context 事件，评测 telemetry 包含 request_contexts，调试日志也输出分项计量。

离线回归覆盖模式切换、完整计量、同一任务中的压缩、工具调用配对、超限拒绝、保存反馈、按日信息筛选、预算续跑、摘要计费、缓存价格和日志持久化。真实三日/五日游的延迟、实际 token 节省及并发收益，需要另行联网对照评测；本次不据离线测试推断这些数值。

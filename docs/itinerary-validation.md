# 行程质量与分日验收

本轮优先解决推荐因素过度阻断、统计口径冲突、重复扣分及长行程返工问题。没有扩展天气、排队、舒适度等体验指标。

## 餐饮策略

默认 `advisory`：每个适用午餐/晚餐时段以 2 家不同候选为目标，评分及价格证据率以 80% 为参考。缺少候选、价格、评分或餐厅身份资料进入餐饮建议，不改变整体状态、评分或 strict 通过结果。

保存时可配置：

```json
{
  "recommendation_policy": {
    "mode": "strict",
    "min_candidates": 4,
    "min_evidence_rate": 0.8
  }
}
```

该片段与 `title`、`days` 等保存参数一起提交。`mode` 可为 `advisory`、`strict`、`off`；数量为 1—20 整数，证据率为 0—1。配置保存到行程 constraints，后续增量保存不必重复提交，显式新设置才能覆盖。旧 `recommendations=true` 采用新的默认建议模式，旧 `false` 关闭推荐质量检查，显式 mode 优先。

只有 strict 模式的候选数量、证据率和要求的餐厅身份核验会产生正式 P1。off 关闭餐饮推荐质量提示，整体预算仍然计入餐饮估算费用。菜品过敏等专项规则本轮没有新增。

候选数量、证据率、餐段、多样性和费用均采用共用的去重集合：同一天、同一餐段、同名同位置只计一次，混合坐标系先统一。同一餐厅跨餐段保留为不同用餐选择，近似相同坐标以五位小数比较。复制候选不会提高覆盖率或改变餐段均价。

## 日期类型与时间线

默认 day_type=full。arrival、departure、transfer 分别表示抵达、离开、转场，须依据已知行程填写 available_start / available_end。抵达只能是实际首日，离开只能是实际末日，转场日须有实际交通时间块；不能仅换类型来规避校验。

完整日继续检查 10:00—18:00（需求单默认要求）。非完整日根据明确的可用时间裁剪覆盖范围，并检查活动是否超出可用时间；离开日不强制新增住宿。候选餐段只统计与当天可用时间有交集的午晚餐。

餐厅候选不占实际时间。用餐、休息、自由活动必须用 rest/free_time 等真实时间块表达。校验和评测共同使用非餐饮时间块的区间并集计算空档；带时间的候选或无时长备注不能掩盖空档，重叠区间也不会产生虚假空档。重叠本身仍按硬错误处理。

## 日内与整体验收

每次保存都会运行本地规则，生成：

- daily：各日问题、分数、日内 strict_pass。
- changed_days：实际内容或约束变动的日期。
- affected_days：本次日期、相邻住宿/出发边界及跨天关联日期，供核对使用。
- repair_days：有明确问题、建议局部修复的日期。
- 整体问题：独立要求的天数与日期、预算、跨天重复及整体 strict 状态。

日内通过不等于整体已完成。可以调用：

```json
{"title":"杭州五日游","scope":"day","day":3,"strict":true}
```

这会返回第 3 天日内验收，并单列跨天关联和整体剩余问题。最终必须使用 `scope=all, strict=true`。只有日内/整体通过的区别，没有跳过真实时间冲突、闭馆、缺失日期或关键证据核验。

当前规则计算不调用外部服务。为了尽早识别跨天问题，每次仍对合并后的已保存行程做完整的本地检查；按日的是报告、修复范围与上下文，不是把相关日期从检查中排除。没有为节省本地计算引入难以失效的验收缓存，也不会因此重新搜索所有天。

跨天重复结合名称、已核验证据 ID 与位置区分；同名但明确异地不直接判重复。身份不明只标待确认。确定重复时优先修本次变动日期，其他日维持日内通过并显示关联，最终整体仍须消除重复。明显可疑的住宿到次日出发衔接会即时提示核对跨天交通，保留关联日期。

同一交通段的赶路过紧、缺少核验交通、空间断层等合并为一个修复根因，保留 related_codes 和条目 ID。独立的错误不会合并。明确错误与资料待确认分开显示，关键资料待确认仍为 P1，不能当作严格通过。

## 按机会数归一化评分

score_version 为 `opportunity-v1`。评分与阻断判定分开：分数按错误密度衡量，strict 仍要求对应范围 P0/P1 为零。

检查对象取自实际非餐饮条目、可定位的相邻停留段、日总体检查和全局一致性检查，形成固定分母；不会因增加问题条数增加分母，也不能靠堆餐厅候选稀释错误。

每个维度中，同一检查对象只按最严重问题计一次损失：P0 为 1，P1 为 0.5，P2 为 0.1。

```text
维度分 = 100 × (1 − 该维度损失之和 ÷ 实际检查对象数)
基础分 = 时间安排×35% + 交通衔接×25% + 资料核验×25% + 行程一致性×15%
总分 = floor(基础分 × 完整度)
```

相同结构、相同缺陷比例的三日和九日行程得分一致。一个问题分摊到更多检查对象上时，扣分较少，但任何硬错误都不能用平均分抵消。维度权重是当前规则参数，不代表经过真实游客体验标定。

完整度按要求日期实际命中比例计算；没有日期区间时按要求天数比例。缺失日期不再额外逐条扣分后又乘完整度，避免重复处罚；缺失日期及天数仍阻断整体交付。

## 版本与回归

新旧公式的基线标记不可比，不计为改善/变差。旧 Web 报告按版本及行程内容签名刷新，只运行本地规则；内存缓存按签名失效，最多保存 200 个摘要。离线复验从约束或标题识别要求天数，不能将半成品的实际天数当作目标。

回归覆盖默认餐饮不阻断与显式严格策略、候选复制、预算去重、真实时间空档、日期窗口、根因聚合、相同缺陷密度、硬错误不被高分掩盖、分日/整体验收、旧日内容保持、关联日期局部修复及旧报告失效。本轮没有启动真实模型/地图联网生成对照，不能将新通过率与旧口径直接比较。

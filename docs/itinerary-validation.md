# 行程质量与分日验收

本轮优先解决推荐因素过度阻断、统计口径冲突、重复扣分及长行程返工问题。没有扩展天气、排队、舒适度等体验指标。

## 必去与闭馆证据

需求单的 mustVisit 会保存到 constraints.must_visit，并参与统一的整体验收。遗漏产生 P1；只有景区子点或含糊别名时标为待确认，不能以餐厅或备注替代游览。按用户确认的策略，明确对应的主景区可满足泛称（如“长城”对应“八达岭长城”）；常规完整名/简称也可匹配，但不会把“国家公园”与“国家博物馆”仅因同前缀判成同一个地点。必去缺项属于全局问题，不污染已经排好某日的日内验收。

旧行程通过 load/validate 或 Web 列表复验时，也读取当前需求单补上要求，报告缓存签名包含这些有效约束。评测支持独立的 must_visit 预期清单，与行程自报清单合并，因此模型不能靠漏填需求单使评测通过。representative 套件版本更新到 2026.11，旧批次快照不改写。

闭馆提取只接受原生口碑工具抓取的外部结果字段，不再扫描工具回显、查询标题或无结果提示。标题可为其对应的正文提供实体关联，但程序生成的展示标题不是外部标题。“全年开放”不表示每周七天开放；否定、历史、其他例外及冲突规则维持未知。明确的“法定节假日除外”以结构化例外保留：普通闭馆日冲突为 P0，带该例外的闭馆日为 P1 待确认，不能推断当天开放。无新规则的其他侧面查询不会抹去已核验规则。

闭馆证据与行程标记采用提取策略版本 3；旧证据即便带 verified=true 也不再当作当前核验依据，旧策略的开放时间负缓存同时失效。重新取证并保存后由程序回填版本，模型自填标记不可信。单纯未知闭馆资料为 P2 待确认，不扣分、不阻断严格验收；已知开放时段/闭馆冲突仍验收。`get_place_reviews(aspect=开放时间)` 对故宫、国博先读取已核对的公开官网入口，返回来源 URL；其他地点继续搜索引擎摘要。官网请求占用同一最多 4 次 HTTP 预算，不额外放大请求数。

## 餐饮策略

默认 `advisory`：每个适用午餐/晚餐时段以 2 家不同候选为目标，评分及价格证据率以 80% 为参考。缺少候选、价格、评分或餐厅身份资料进入餐饮建议，不改变整体状态、评分或 strict 通过结果。

保存时可配置：

```json
{
  "recommendation_policy": {
    "mode": "strict",
    "min_candidates": 4,
    "min_evidence_rate": 0.8
  }
}
```

该片段与 `title`、`days` 等保存参数一起提交。`mode` 可为 `advisory`、`strict`、`off`；数量为 1—20 整数，证据率为 0—1。配置保存到行程 constraints，后续增量保存不必重复提交，显式新设置才能覆盖。旧 `recommendations=true` 采用新的默认建议模式，旧 `false` 关闭推荐质量检查，显式 mode 优先。

只有 strict 模式的候选数量、证据率和要求的餐厅身份核验会产生正式 P1。off 关闭餐饮推荐质量提示，整体预算仍然计入餐饮估算费用。菜品过敏等专项规则本轮没有新增。

候选数量、证据率、餐段、多样性和费用均采用共用的去重集合：同一天、同一餐段、同名同位置只计一次，混合坐标系先统一。同一餐厅跨餐段保留为不同用餐选择，近似相同坐标以五位小数比较。复制候选不会提高覆盖率或改变餐段均价。

## 日期类型与时间线

默认 day_type=full。arrival、departure、transfer 分别表示抵达、离开、转场，须依据已知行程填写 available_start / available_end。抵达只能是实际首日，离开只能是实际末日，转场日须有实际交通时间块；不能仅换类型来规避校验。

完整日以 10:00—18:00 为白天覆盖的节奏参考，不是活动上限或返店截止，30分钟浮动也不表示18:30必须结束。用户未限制晚间时，按兴趣、体力及当地夜间特色安排适量晚餐后活动或可选夜游，核验开放与返程；不强制每天加夜游。参考开始/结束边界允许 30 分钟浮动；再晚开始或早结束但缺口不超过参考窗口 25% 时，只列 P2 提醒、不扣分、不阻断。对于默认 8 小时窗口，17:40/17:50 返店没有问题，16:45 返店只是提醒；缺口超过 2 小时或没有有效活动仍为 P1，防止半日空缺冒充完整日。该规则不要求为卡点填休息。非完整日根据明确的可用时间裁剪参考范围；available_start/end 只记录用户明确要求或已确认到离交通的硬边界，未知留空，不得把模型估排的18:00/18:30作息写入。明确边界越界仍按 P1 处理。离开日不强制新增住宿。候选餐段只统计与当天可用时间有交集的午晚餐。

餐厅候选不占实际时间。用餐、休息、自由活动必须用 rest/free_time 等真实时间块表达。校验和评测共同使用非餐饮时间块的区间并集计算空档；带时间的候选或无时长备注不能掩盖空档，重叠区间也不会产生虚假空档。重叠本身仍按硬错误处理。

住宿到达/离开可用 `time` 表达时间点，未填结束时间时结束边界等于该时间，不要求编造停留时长。例如 18:00 到酒店可覆盖日末，早晨酒店锚点可作为后续交通的出发边界。显式 end_time 或 planned_duration_min 优先；只有酒店仍不能构成有效游览日。

路线所需时长与预留时长的差值同时不超过 5 分钟及路线时长的 10% 时，`route-duration-too-short` 为 P2 建议；超过任一限制仍为 P1。`save_itinerary(route_tolerance_min=..., route_tolerance_ratio=...)` 可配置并持久化，范围分别 0–15 分钟、0–0.25，任一设 0 即严格比较。该容差只适用于路线时长差异，不豁免活动重叠、开放时间和可用时间边界。

`save_itinerary(repair_routes=[日期])` 复用已有真实证据补交通和顺延冲突条目，不重新联网；保留活动时长及已分配交通缓冲，其他日期不重排。固定时刻用 `time_locked=true` 标记，仅限用户指定/已确认预约、车次，模型估排时间不锁定。自动修复若需越过固定时刻、开放时间、已知可用边界或跨午夜，拒绝整次修改并保留原版本，要求局部调整；不会靠降低评级或缩短游览把它改成通过。

全天活动时长统计游览、交通及其他活动，不含住宿锚点、用餐候选、休息和备注。10 小时为节奏目标，超出目标 20% 以内（不超过 12 小时）为 P2 提醒、不扣分、不阻断；超过 12 小时才产生 P1。10 小时 17 分钟只比目标超出约 2.8%，不要求仅为该提示重排。此放宽不豁免真实时间重叠、闭馆、赶不上交通或中间大段未规划空档。

## 酒店身份与策略

需求单 `allowHotelChanges` 默认为 false，全程沿用同一酒店；只有用户允许时设 true。保存将该策略写入 constraints.allow_hotel_changes，不能用单次保存覆盖需求单。不同酒店产生 P1 `hotel-change-not-allowed`，不静默替换成第一家；整份行程一致重新选一家仍允许。

酒店 `name` 保留真实名称，返回/出发/退房写 `activity`。有明确同酒店身份时兼容旧的“回到某酒店”写法，归一地点及交通端点并重新绑定已有证据。未知酒店不凭动作文本创造证据，冲突的证据 ID/坐标不继承。早晚锚点同一酒店同一晚只计费一次；参考价仍为每房每晚。旧路线 ID 失效时，只允许用实际端点及交通方式一致的已核验新路线重绑定，不能借用另一酒店的路线。

## 日内与整体验收

每次保存都会运行本地规则，生成：

- daily：各日问题、分数、日内 strict_pass。
- changed_days：实际内容或约束变动的日期。
- affected_days：本次日期、相邻住宿/出发边界及跨天关联日期，供核对使用。
- repair_days：有明确问题、建议局部修复的日期。
- 整体问题：独立要求的天数与日期、预算、跨天重复及整体 strict 状态。

日内通过不等于整体已完成。可以调用：

```json
{"title":"杭州五日游","scope":"day","day":3,"strict":true}
```

这会返回第 3 天日内验收，并单列跨天关联和整体剩余问题。最终必须使用 `scope=all, strict=true`。只有日内/整体通过的区别，没有跳过真实时间冲突、闭馆、缺失日期或关键证据核验。

当前规则计算不调用外部服务。为了尽早识别跨天问题，每次仍对合并后的已保存行程做完整的本地检查；按日的是报告、修复范围与上下文，不是把相关日期从检查中排除。没有为节省本地计算引入难以失效的验收缓存，也不会因此重新搜索所有天。

跨天重复结合名称、已核验证据 ID 与位置区分；同名但明确异地不直接判重复。身份不明只标待确认。确定重复时优先修本次变动日期，其他日维持日内通过并显示关联，最终整体仍须消除重复。明显可疑的住宿到次日出发衔接会即时提示核对跨天交通，保留关联日期。

同一交通段的赶路过紧、缺少核验交通、空间断层等合并为一个修复根因，保留 related_codes 和条目 ID。独立的错误不会合并。明确错误与资料待确认分开显示，关键资料待确认仍为 P1，不能当作严格通过。

## 按机会数归一化评分

score_version 为 `opportunity-v9`。本次加入按字段、适用日期回填的开放事实及明确临时闭馆公告；公告与行程日期冲突仍为P0，未知不当作闭馆。粗排兑现、全局占用、排除和重游统一校验；骨架不计完成度，缺失粗排日期不重复扣分。重游不再凭repeat_reason豁免，必须有宿主根据真实用户消息保存的授权。已确认的跨日重复、预留冲突和同日主子点拆分在普通保存也拒绝提交，分级仍为P1，不将所有P1改成硬错误。包含关系参与主目的地数量和评分机会计数。交通引用检查相邻停留点一致性，并给具体修复参数；日程边界和全天时长采用上述容差，三种节奏提示的P2不扣分，其P1仍计入。未知闭馆资料与法定节假日例外待确认不扣分，轻微路线差异降为建议；旧版本报告需重算，不把口径变化直接算作质量改善。分母剔除非核心活动，路线证据归入交通维度。strict要求对应范围P0/P1为零，不设总分通过门槛。

检查对象取自主目的地、住宿地点、定时主停留点之间的交通段、日总体检查和全局一致性检查。休息、自由活动、备注、餐饮候选不增加分母；拆分交通块、重复住宿锚点、主景区内部子点也不增加分母。缺坐标的主停留点仍计入检查，不能靠删坐标避开路线机会。非核心条目的时间冲突、越界等仍核验，问题归入当天对应检查对象，不因排除分母而免责。

每个维度中，同一检查对象只按最严重问题计一次损失：P0 为 1，P1 为 0.5，P2 为 0.1。

```text
维度分 = 100 × (1 − 该维度损失之和 ÷ 实际检查对象数)
基础分 = 时间安排×35% + 交通衔接×25% + 资料核验×25% + 行程一致性×15%
总分 = floor(基础分 × 完整度)
```

相同结构、相同缺陷比例的三日和九日行程得分一致。一个问题分摊到更多检查对象上时，扣分较少，但任何硬错误都不能用平均分抵消。维度权重是当前规则参数，不代表经过真实游客体验标定。

完整度按要求日期实际命中比例计算；没有日期区间时按要求天数比例。缺失日期不再额外逐条扣分后又乘完整度，避免重复处罚；缺失日期及天数仍阻断整体交付。

## 版本与回归

新旧公式的基线标记不可比，不计为改善/变差。旧 Web 报告按版本及行程内容签名刷新，只运行本地规则；内存缓存按签名失效，最多保存 200 个摘要。离线复验从约束或标题识别要求天数，不能将半成品的实际天数当作目标。

回归覆盖默认餐饮不阻断与显式严格策略、候选复制、预算去重、真实时间空档、日期窗口、根因聚合、相同缺陷密度、硬错误不被高分掩盖、分日/整体验收、旧日内容保持、关联日期局部修复及旧报告失效。本轮没有启动真实模型/地图联网生成对照，不能将新通过率与旧口径直接比较。

## 主景区内部推荐与远郊日

景点搜索优先使用供应商父 POI ID，或明确的景区名称前缀（如「故宫博物院-大石雕」）归并。只有搜索结果中同时存在真实主 POI 才合并；主 POI 保留自己的名称、坐标、评分和证据，不能用子点高分充当主景区评分。缺少主 POI 时保留子点并提示核验主景区，不虚构主景区地点。无归属字段或明确前缀的地点不按距离猜归属。

保存一个主景区visit，`recommended_spots`存内部可选地点名称（最多10个，每个不超过100字），以主景区总游览时间包住内部游览。内部推荐在Markdown、单日摘要、旅行状态和Web侧栏显示，不生成额外地图停留点和路线；内部不同票制、开放时间仍需在说明中告知用户。工具证据维护独立的完整包含关系 `contained_visits`，行程中的 `parent_visit` 由程序回填，不接受模型自报的包含关系。主子点共享主目的地身份，同日拆成两个独立visit拒绝保存；跨日仍需真实用户的重游授权。仅保存子点不自动满足整个主景区必去要求。旧行程不静默删条目或扩大游览时间，需按具体冲突把子点归入推荐；计分和统计使用同一包含关系。

远郊识别仍以单程 ≥40 公里为主；未知距离时单程 ≥90 分钟，或至少两段 ≥60 分钟且合计 ≥150 分钟兜底。普通城市日单段超过 150 分钟为 P1；包含游览的远郊日默认单段上限 240 分钟，超过才是 P1；60 分钟以上的长通勤始终保留 P2 提醒。实际 `time/end_time` 优先于 `planned_duration_min`，不能通过省略或压低后者绕过阈值。

`save_itinerary(remote_leg_limit_min=...)` 可配置远郊单段上限，范围 60–480 分钟，持久化到 constraints；不会改变普通城市日上限。单主景区、附近轻活动是节奏建议，远郊点数或回城后加点不再直接阻断。已完成远郊日不要求用休息凑满统一的 day_end；当天 available_start/end、实际路线耗时、闭馆、开放时间、冲突、全天活动总时长仍照常核验。普通日的首尾覆盖也不能靠休息、自由活动或备注填充。

没有热门景区白名单：长城等特色目的地适用同一远郊时间预算机制，必去要求确保不被简单删掉，但热门/必去不豁免真实交通和开放约束。


## 增量修订与无变化保存

`merge=true` 且不是 `merge_mode=replace_day` 时，指定已有日期和稳定条目id，可以只传修改字段（例如 `{ "id": "d1-museum", "end_time": "12:30" }`）。程序从已有条目补齐其他字段，再走相同证据绑定和完整校验。仅当名称、类型未改变时继承，避免换地点后沿用旧身份；未知id、无日期或整天替换仍须提交完整条目。

内容、约束和证据均未变化且四份交付文件齐全、质量报告版本/签名有效时，原样保存沿用现有版本，不写文件。真实修改、证据更新、缺失交付文件或旧报告仍更新；版本冲突检查与strict拒绝规则照常，不能靠无变化保存绕过验收。

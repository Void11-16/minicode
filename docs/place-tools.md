# 参观资料与口碑工具拆分

更新日期：2026-11-10。

原来的 `get_place_reviews` 同时查开放规则、时长、消费和体验，停止条件也混在一起。现在按问题分成两个工具，底层仍共用搜索、正文读取、导航与缓存，避免复制两份爬取实现。

## 入口与返回

| 工具 | 职责 | 参数 | 不负责的内容 |
| --- | --- | --- | --- |
| `get_place_visit_info` | 开放时段、闭馆日、最后入场、表演场次、临时公告、建议游玩时长 | `place`、`city`、`fields`、`visit_date`、`refresh` | 口碑和餐饮体验 |
| `get_place_reviews` | 口碑、人均消费、招牌菜、排队 | `place`、`city`、`aspect`、`refresh` | 开放规则、公告、游玩时长 |

参观资料示例：

```json
{
  "place": "陕西历史博物馆",
  "city": "西安",
  "fields": ["hours", "closure", "last_admission"],
  "visit_date": "2026-11-12"
}
```

`fields` 可选值为 `hours`、`closure`、`last_admission`、`sessions`、`notices`、`visit_duration`。省略时普通地点查询开放时段，博物馆增加闭馆日，表演类增加场次。时长只有显式请求时才成为完成条件；同页存在时会顺带提取，不单独补搜。日期用于公告检索，入库的日期、季节和星期条件仍由行程绑定及校验层判断适用性。

返回内容包括来源链接与原文摘要、逐字段状态和证据 ID、可选时长参考。有效开放事实写入证据仓库，保存行程时回填；没有依据和访问失败分别处理。口碑工具只返回体验资料及参考热度，不把页面中的开放时段或闭馆文字写成结构化事实。

口碑示例：

```json
{"place":"某餐厅","city":"西安","aspect":"排队"}
```

`aspect` 仅支持 `口碑`、`人均价格`、`招牌菜`、`排队`，省略为口碑。人均消费不能替代酒店的每房每晚价格。

旧的 `get_place_reviews(aspect="开放时间")`、`get_place_reviews(fields=...)` 会返回 `PLACE_REVIEWS_WRONG_TOOL`，提示正确工具；参观工具传 `aspect` 返回 `VISIT_INFO_USE_FIELDS`。没有保留能暗中执行旧职责的运行入口。已持久化的历史开放事实继续使用；旧日志中的时长和审计参数只作为历史数据读取。

## 共享来源与停止条件

默认注册表创建一个 `PlaceSourceClient`，供两个工具共同使用：

1. 先复用该地点已有来源和已读正文，按当前问题选择开放片段或体验正文。
2. 参观开放资料保留已验证直达入口、搜索摘要、网页正文以及首页到参观指南的导航流程。
3. 若仍未回答所需问题，再尝试搜索来源。参观字段逐项检查，体验问题分别检查消费数值、菜品描述、排队依据或口碑描述；不再要求凑满三个链接。
4. 单次最多 **4 次来源请求**，同一任务同一地点两类工具合计最多 **8 次**。搜索、正文、跳转共用额度，换字段、换工具和 `refresh=true` 不重置。可注入的搜索适配器也必须自行限制内部重试，适配器调用计一次来源请求。
5. 查询和网页缓存有效期 **30 分钟**，复用保留原采集时间。任务通过 `queryAttempts` 隔离；无任务账本的 MCP 等调用按证据仓库隔离，来源预算随缓存窗口重置。新任务建立新的任务作用域。

来源缓存为内存缓存；结构化开放事实和查询结果仍使用原有证据持久化机制。它不保证进程重启后继续复用所有原始网页。

同一来源的正文同时保留开放片段、体验文本、时长片段和导航链接。后续换工具读取的是已有页面的另一种投影，不再次请求该页面。错误响应和验证码不作为成功空结果缓存，验证码退避也明确保留访问失败状态。

诊断记录增加 `place_lookup`：`kind`、`requests`、`cache_hits`、`entity_requests`、`entity_limit`。它记录来源层请求与缓存情况；实际 HTTP 成功率继续用 HTTP 埋点统计，两者不混同。

## Agent 配套策略

默认旅游规划只暴露当前日已选点和必去点尚缺的参观资料，不逐个查询所有候选口碑。已查无依据的缺口保留待确认。用户明确要求体验或严格餐饮时才保留口碑工具；明确查询时长或开放资料可以放开参观查询范围，不连带放开一般口碑。收敛阶段仍保留必要参观资料，工具目录限制和后端拦截保持一致。

普通聊天仍可按工具目录发现两个入口。CLI、Web 和 MCP 使用相同注册表与实现；提示词、工具探测和历史日志审计已同步调整。

## 验证边界

`test/place-tools-split.test.ts` 验证职责参数、一次命中停止、顺带回填、真实注册表的跨工具正文缓存、原采集时间、地点总预算、验证码及官网 HTTP 失败状态，也检查时长参考不会被标成已核验开放规则。现有开放字段、官网导航、行程保存和 Agent 测试继续覆盖实际调用路径；`test/travel-efficiency.test.ts` 另验显式时长请求不开放一般口碑。

这些是固定响应回归测试，验证工程行为；没有据此宣称真实搜索覆盖率或真实旅游规划质量已经提升。

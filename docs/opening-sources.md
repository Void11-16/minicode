# 开放信息与搜索来源

## 当前实现

`opening-facts.ts`将hours（时段）、closure（每周闭馆）、last_admission（最后入场）、sessions（演出场次）、notices（临时闭馆）分别保存到证据仓库。记录包含地点ID/规范名、城市、状态、适用日期/星期（可明确提取的时段）、URL、原文引用与采集时间；模型参数不能写入这些证据。查询结果缓存30分钟，缓存过期不直接撤销已保存事实。

状态分为verified、not_found、conflicting、needs_confirmation。verified表示程序找到了当前提取规则支持的可追溯表述，不代表现实营业状态获得保证。官网、政府页面、平台、地图和普通搜索来源分级；同等级开放时段选择较早闭园的来源，其他字段冲突维持待确认，低级别搜索摘要不覆盖高级别已知事实。招聘/其他场馆规则不回填到所选地点，无URL的普通摘要不标核验。既有当前版本闭馆证据继续兼容，不冒充新查询产生的带URL字段。

保存按实际行程日期回填时段、最后入场、场次与闭馆日期，并记录opening_evidence_ids；后续缺字段的地图结果不会清空网页事实。24:00只允许作为开放结束，场地全天开放与喷泉/演出场次分别展示。季节范围、条件化入场/场次不能可靠表达时保持待确认，不简化为全年规则；尚不支持任意自然语言公告的完整推理。

提取策略版本3保留网页块、表格行/单元格和标签边界，按含时间事实的正文选片段，不再取文档前四个“开放时间”关键词。导航、票价新闻和交通通行时间不能冒充场馆开放时间。标签与数值分项展示的开馆、闭馆及停止入馆时间可以组合；明确的每年月日范围保留start_month_day/end_month_day，支持跨年、季节边界和闰日，日期/星期表头也约束后续行。没有旅行日期时，不将某个季节的窗口当作通用值。

last_admission保留兼容的无条件字符串，或带日期/星期/月日范围的规则数组；保存时按访问日期选择，内部场馆的截止不覆盖主景区。公告中的明确子区域主语、局部关闭和机构署名分别处理，不以页面所属官网或落款推断整个景区停业。“某日起停止开放”只在对应实体上保留有起点、无已知终点的闭馆范围。旧版本字段与开放查询缓存不复用，避免继续使用误归属公告或解析失败的负结果。

搜索/官网响应读取有字节上限，验证码标题与验证域名作为CAPTCHA服务错误记录，HTTP200仍只代表传输成功。所有来源均失败或被验证拦截时，不生成not_found字段及其30分钟负缓存；原任务的两次预算仍生效。部分字段未找到是returned或unavailable，不再因为结果文字中含“未找到”而统称服务失败。

真实网页回归样本为test/fixtures/palace-visit-20261103.html，保留2026-11-03官网原始导航、公告和时刻表DOM，来源及原页哈希见同名JSON。回归经过真实Registry、证据持久化、save、重新加载和最后入场校验；还验证其他场馆表格、范围边界、子区域公告、验证码恢复和旧版本失效。此次真实故宫查询由4次来源HTTP、未提取hours，变为1次官网HTTP、正确提取季节hours/last_admission；单样本不代表所有网站覆盖率。

实际使用的开放信息在JSON、Markdown和Web时间线中保留。明确临时闭馆与访问日期冲突进入原有P0校验；已知开放窗口仍检查完整停留，未知字段不伪造关闭结论。字段事实及负结果加入压缩后的动态证据摘要，减少重复搜索。

`get_place_reviews(fields=...)`可按缺口组合查询，一次结果顺带保存其他可验证字段。默认检查所有当前日已选地点，普通地点查hours，博物馆等加closure，喷泉/演出加sessions；最后入场和临时公告会顺带提取，也能显式请求。单地点的不同字段共用两次查询/复用预算；单次最多4次来源请求，官网和可选搜索适配器都占此预算。新的API适配器不应自行隐藏多轮抓取和重试，否则会破坏预算口径。

优先复用已保存的地图与网页字段，仅搜索缺口。保留故宫/国博固定官网入口，其余开放查询依次使用Bing→百度→DuckDuckGo→360，取得所需字段即停止。支持百度现代卡片的落地页与服务端摘要数据。单条有URL、地点对应、时间清楚的普通来源即可回填，不要求官网或多来源交叉确认。模糊来源不否定其他清楚的字段，多个时段按来源等级选择，同等级采用较早闭园的一条。

摘要不足时，在同一4次来源请求预算内读取最多2个相关页面，优先提取文章正文并排除推荐列表。正文连接只允许公共HTTP/HTTPS地址，不跟随重定向，设置读取上限与超时。ReviewSearchProvider仍可注入，尚未接入新的付费API、浏览器渲染或OCR。

## 搜索API选择

2026-11-03核对官方公开文档，以下是能力比较，尚无本项目的同题覆盖率或准确率实测。

| 候选 | 适合测试的用途 | 边界 |
| --- | --- | --- |
| [博查](https://bochaai.com/)；[官方文档](https://aq6ky2b8nql.feishu.cn/wiki/HmtOw1z6vik14Fkdu5uc9VaInBb) | 中文本地信息候选；官方目录提供Web Search和Fetch网页读取能力 | 南昌等城市的覆盖、可用性、正文质量、套餐与费用需实际验证，不能仅按中文定位断定最好 |
| [Tavily](https://docs.tavily.com/documentation/api-reference/endpoint/search) | 搜索与正文提取组合；支持相关片段、可选raw_content、域名和日期筛选，另有Extract接口 | 中文本地覆盖需对照；raw_content增加耗时，生成答案不能代替原始来源 |
| [Serper](https://serper.dev/) | 补充Google搜索索引；结构化organic标题/链接/摘要便于过滤推广与聚合结果 | SERP返回不等于目标正文可读，也不保证官网和最新公告可访问 |

优先用博查与Tavily对同一批地点做小样本对照，Serper作为第二索引候选。上线前检查部署环境的访问、计费与限额；不预设某家已经胜出，不同时对所有地点并发请求三家服务。

## 官网难找或难读时

搜索、正文获取和事实提取是三个环节，换搜索API主要改善前者。结果过滤广告后，按实体匹配和来源可信度选择场馆参观说明、票务须知、政府/文旅公告、可靠票务平台，不把“必须找到官网”设为通过条件。官网权重更高，但搜索摘要可能过期或截断，旧公告也可能不适用于旅行日期。

正文读取已接入同一请求预算，对缺口换来源，不递归整站抓取。图片公告或动态页面需要单独的OCR/渲染能力；登录、验证码、信息矛盾和没有日期条件等情况保持待确认，不靠无限重试或生成答案补齐。

比较时分别记录来源返回率、包含正文来源的调用比例、请求字段提取率、最终行程保留率、人工核对正确率，以及请求数、时延和费用。前三类机器指标不能替代事实正确率；HTTP200、搜到官网或返回很多链接均不足以证明开放信息可靠。
